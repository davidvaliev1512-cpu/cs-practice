Рабочая папка содержит файлы, которые вы сейчас редактируете.
Индекс хранит версии файлов, выбранные для следующего коммита.
Коммит сохраняет снимок подготовленных файлов в истории Git.

## Git и GitHub

Git записывает историю изменений на моём компьютере. С его помощью я могу делать коммиты, смотреть изменения и работать с ветками. GitHub хранит опубликованную копию репозитория. Мои коммиты появляются там после `git push`.

До `git add` я посмотрел `git diff`. Эта команда сравнивает файл на диске с версией в индексе. После `git add` команда `git diff --staged` сравнивает индекс с последним коммитом. Те же добавленные строки теперь видны среди изменений, подготовленных к коммиту.

## Использованные команды

- `git status` показывает текущую ветку и состояние файлов. По нему видно, какие файлы новые, какие изменены и какие уже добавлены в индекс.
- `git diff` показывает правки в отслеживаемых файлах, которые ещё не попали в индекс.
- `git diff --staged` показывает подготовленные изменения. По ним можно проверить, что попадёт в следующий коммит.

## Ветки

Ветка — это указатель на коммит. Когда я создал новый коммит в `explain-branches`, эта ветка стала указывать на него, а `main` осталась на предыдущем коммите.

Слияние включает изменения из `explain-branches` в `main`. С флагом `--no-ff` Git создаёт отдельный коммит слияния с двумя родителями, по которым видна история обеих веток.
