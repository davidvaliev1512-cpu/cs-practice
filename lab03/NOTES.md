# Лабораторная работа №3

## Три состояния калькулятора

Сначала добавил сложение (`fe64d02`), затем вычитание (`c6f822e`) и умножение (`4fcd015`). Каждый раз использовал `git add lab03/calc.py` и `git commit`. На числах 8 и 2 проверил, что по мере добавления операций программа выводит сумму 10, разность 6 и произведение 16.

## Сравнение версий и поиск изменений

- `git log --oneline --stat` показал историю с короткими хешами, сообщениями и числом изменённых строк по файлам. В начале списка были три коммита калькулятора.
- `git diff HEAD~2 HEAD -- lab03/calc.py` сравнил версию со сложением с версией, где уже есть три операции. В разнице видны добавленные функции и вывод вычитания и умножения.
- `git show HEAD~1` показал один коммит `c6f822e`, его автора, дату, сообщение и изменения. В этом коммите появилось вычитание.
- `git log -S"def" --oneline -- lab03/calc.py` нашёл все три коммита по калькулятору. В каждом менялось количество вхождений `def`, потому что добавлялась функция.
- `git blame lab03/calc.py` показал для каждой строки, какой коммит изменил её последним. Сложение пришло из `fe64d02`, вычитание из `c6f822e`, умножение из `4fcd015`.

По `log` удобно найти нужный коммит, по `show` посмотреть его содержимое, а по `diff` сравнить две выбранные версии.

## Восстановление файла

Удалил из `calc.py` две строки вывода и оставил правки вне индекса. `git status` показал изменённый файл. `git restore lab03/calc.py` взял копию из индекса и вернул обе строки. Индекс в этот момент совпадал с последним коммитом.

`git restore --source=HEAD~2 lab03/calc.py` взял файл из явно указанного коммита `c6f822e` и положил его в рабочую папку. `git diff` показал исчезновение кода умножения. При повторном обычном `git restore lab03/calc.py` умножение вернулось из индекса.

Обе команды в таком виде перезаписывают рабочую копию файла. Мои незакоммиченные удаления исчезли после первого восстановления.

## Ошибочный коммит и отмена

В коммите `5ae10a2` добавил обычное деление и на входе 8 и 0 получил `ZeroDivisionError`. После `git revert HEAD` в `git log --oneline` остались и ошибочный коммит, и новый `bdd10f3`, который убрал деление. На тех же числах три оставшиеся операции снова выполнились без ошибки.

`git reset --hard <коммит>` передвигает указатель текущей ветки на выбранный коммит и заменяет индекс и отслеживаемые файлы его версиями. При этом незакоммиченные правки в этих файлах могут пропасть. Если более новый коммит уже опубликован, такой откат расходится с историей на GitHub. `git revert` добавляет обратную правку поверх существующей истории, поэтому результат можно отправить обычным `git push`, а ошибку и её исправление видно в журнале.

## Тег рабочей версии

`git tag -a v1.0 -m "Рабочая версия калькулятора"` отметил версию со сложением, вычитанием и умножением после отмены ошибочного деления. `git tag` вывел `v1.0`, а `git show v1.0` показал сообщение тега и коммит `640bee6`. Сначала отправил ветку командой `git push origin main`, затем тег командой `git push origin v1.0`.

Ветка передвигается на новый коммит, когда я делаю коммит в этой ветке. Тег `v1.0` остаётся на выбранном коммите, поэтому по нему можно вернуться к версии с тремя операциями и после следующих изменений в `main`.

## Эксперимент в ветке

`git switch -c experiment` создал отдельную ветку. В ней добавил деление с проверкой второго числа. Для 8 и 2 калькулятор выдал частное 4. Для 8 и 0 он вывел сообщение «На ноль делить нельзя.» и завершился без ошибки. Правку сохранил командой `git commit -am "Add safe division"`.

`git switch main` возвращает рабочую папку к версии из `main`, где до слияния было три операции. `git merge --no-ff experiment` переносит проверенную правку в `main` отдельным коммитом слияния. После слияния команда `git branch -d experiment` удаляет имя ветки, а её коммит остаётся доступен через `main`.
